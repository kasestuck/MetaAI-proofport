## Release audit scope

`python -m backend.release audit` reads current tracked files and every distinct
Git blob reachable from local refs. It checks tracked env/generated names, the
actual known local Meta key (raw/JSON/base64) and common credential prefixes.
It reports counts only, never key values or matching source lines. An exact
known-key scan is not exhaustive secret discovery, and local refs are not proof
of every server-side/deleted object. No Git history is rewritten.

Initial inventory: **231 tracked files**, no `.work`, `.tmp`, `.venv`, cache,
compiled-Python or private-env files tracked. Generated work and the key already
on disk remain untouched and ignored. Final inventory changes because release
documentation/tools/tests are added; rerun the audit after committing.

The root ignore rules intentionally do not exclude source, tests, Markdown,
reviewed fixtures or arbitrary JSON/evidence fixture files. `.env.example` is
tracked with an empty key and mock default. No `.env` was edited.

License inventory comes from installed package metadata, with full licenses
remaining in upstream distributions. No runtime third-party frontend bundle/font
was found. `pip check` is consistency checking, not a comprehensive CVE audit.
Docker image transitive dependencies are not fully locked: existing image IDs
are pinned during runs and code/image changes require fresh receipts.
